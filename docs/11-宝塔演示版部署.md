# 宝塔部署：当前演示版

日期：2026-11-03。此次部署保留现有演示功能和最新场景素材，不接入共享数据库或真实内容审核。

## 部署包

上传包包含 `src/`、`public/`、依赖锁文件、Next.js／TypeScript 配置和本说明；不包含生图密钥、环境私密文件、原始制作素材、开发依赖目录或 Windows 构建目录。在目标 Linux 服务器上安装依赖和构建，避免把 Windows 原生依赖复制到 Linux。

服务器运行不需要 `GATEWAY_API_KEY`，也不会调用生图服务。

## 宝塔操作

1. 确认服务器现有站点、目录和端口，使用独立项目目录，避免覆盖其他项目。
2. 在宝塔安装／选择 Node.js 22 LTS，将源码包上传并解压到项目根目录；该目录下应直接有 `package.json`、`src/` 和 `public/`。
3. 在使用 Node.js 22 的终端中进入项目根目录，依次执行：

   ```bash
   npm ci --include=dev
   npm run build
   ```

4. 在宝塔“网站 → Node 项目”添加项目，选择项目根目录、Node.js 22 和 `start` 脚本。现有脚本运行 `next start --hostname 127.0.0.1`；若 3000 已占用，使用自定义启动命令 `npm run start -- --port 可用端口`。
5. 使用宝塔的项目进程守护，确认项目运行及重启后能恢复；不要同时另开第二个进程占用同一端口。
6. 绑定用户指定的域名，将宝塔 Nginx 反向代理指向 `http://127.0.0.1:项目端口`。域名解析需指向该服务器，不改动其他站点。
7. 有域名时配置有效 HTTPS 证书。用户本次选择暂用 IP：演示版已为身份和提交标识增加 `crypto.getRandomValues()` 兼容路径，普通 HTTP 不再依赖仅安全上下文可用的 `crypto.randomUUID()`。

### 本次 IP 访问配置

服务器为 `101.37.156.220`，Ubuntu 22、2 核、约 1.7 GB 内存；宝塔现有 `panel_ssl_site` 是证书辅助站点，保留不改。建议新建项目目录 `/www/wwwroot/mouse`，Node 项目内部端口 3000。添加 HTML 站点，域名栏填 `101.37.156.220:8080`，根目录使用独立空目录 `/www/wwwroot/mouse-web`，在该站点添加反向代理到 `http://127.0.0.1:3000`；此站点目录不要指向源码，避免源码被静态公开。宝塔防火墙和阿里云安全组均放行入站 TCP 8080，访问 `http://101.37.156.220:8080`，无需对外开放 3000。

## 更新与回退

更新时使用独立的新版本目录，安装构建成功后再切换宝塔项目路径并重启。保留上个可运行版本；失败时将项目路径切回并重启，不删除旧站点或目录。

## 当前边界

内容、金币、评价和举报保存在当前标签页 `sessionStorage` 中，不在服务器共享；演示审核台也只操作本地数据。此包可以公开试玩，但不代表正式多人社区后端已经完成。
