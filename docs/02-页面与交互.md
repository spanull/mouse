# 页面与交互设计

本文依据产品需求中的建议基线设计。角色形象、配色和名称需在正式美术制作前确认。

## 1. 视觉方向

- 场景：温暖、轻松的小院，使用有限色板和统一像素尺寸。
- 像素美术用于角色、道具、边框和小装饰；内容区使用清晰的常规中文字体。
- 内容面板保持足够留白与对比度，避免把长文章放进像素对话气泡。
- 首版只制作一个固定场景，不做地图移动和拖拽探索。

## 2. 首页结构

```text
┌─────────────────────────────┐
│ 像素小院             设置   │
│                             │
│    [吃瓜摊]     [留言牌]    │
│                             │
│          像素主角           │
│        点击我，逛逛小院     │
│                      [信箱]│
│                             │
├─────────────────────────────┤
│  吃瓜广场  留言板  我的信箱 │
└─────────────────────────────┘
```

底部文字入口与场景热点指向相同功能，保证用户不用猜图标含义。窄屏优先保证角色和热点可见，使用响应式位置，不能仅按固定屏幕坐标放置按钮。

小院和角色由 PixiJS 画布渲染，文字标签、热点按钮及业务内容由 React HTML 层承载。HTML 热点随场景坐标变换同步定位，点击与键盘操作调用同一业务入口，避免画布和覆盖按钮重复处理同一次操作。

## 3. 页面与路由建议

| 路由 | 内容 | 主要操作 |
| --- | --- | --- |
| `/` | 小院场景 | 点击角色、场景入口、设置 |
| `/topics` | 吃瓜广场 | 浏览、加载更多、发布 |
| `/topics/new` | 发布话题 | 输入、校验、提交 |
| `/topics/[id]` | 话题详情 | 浏览评论、评论、举报 |
| `/board` | 留言板 | 浏览、发布留言 |
| `/board/[id]` | 留言详情 | 浏览回复、回复、举报 |
| `/inbox` | 我的信箱 | 我的内容、收到的回复 |
| `/admin` | 内容管理 | 登录后审核、隐藏、处理举报 |

路由可刷新和直接打开。移动端内容页采用全屏面板视觉，桌面端采用居中面板；首版不依赖复杂的路由拦截弹窗。

从列表返回时尽量保留滚动位置。发布表单有未提交内容时，离开页面提示是否放弃；输入默认仅保存在当前页面内存，不自动保存到共享设备的长期存储。

## 4. 角色状态机

| 状态 | 动画建议 | 触发 | 结束行为 |
| --- | --- | --- | --- |
| idle | 轻微呼吸、偶尔眨眼 | 页面可见且无其他动作 | 循环 |
| pressed | 短暂下蹲或跳跃 | 点击角色 | 回到 idle |
| success | 开心、举手或爱心 | 提交请求已成功 | 回到 idle |
| error | 疑惑表情或气泡 | 提交失败 | 回到 idle |
| static | 保留关键姿势 | 减少动态效果或动画不可用 | 使用文字状态反馈 |

- 点击角色后立即显示操作气泡；动作完成不作为打开入口的前置条件。
- success 代表“请求已提交成功”，不代表审核通过。
- 非首页表单可以展示小号角色反馈；首页角色不可见时不在后台播放庆祝动画。
- 短动作优先级：success/error 高于 pressed，pressed 高于 idle。
- success/error 播放期间忽略新的装饰性点击动作，但业务按钮仍可使用。
- 短动作不排队；播放结束后复位。页面卸载时清理定时器和事件监听。
- 多次点击主角只保留一个操作气泡，不重复弹出面板。

## 5. 动画的两阶段实现

### 原型阶段

先建立 PixiJS 场景与 React 的交互边界，使用静态 PNG 或自制占位图作为 Sprite，通过场景 ticker 做微幅浮动和短跳；没有正式动作图时，用少量自制占位帧验证 AnimatedSprite 播放和完成回调。保持画布布局尺寸不变，CSS 用于 HTML 气泡与按钮反馈。

可选参考值：待机周期约 2～3 秒，点击动作约 250～400 毫秒。这些数值供调试，不构成必须模仿的视觉效果。

### 正式素材阶段

将正式精灵图转换为有序纹理帧，交给 PixiJS AnimatedSprite 播放待机、点击和成功动作；按素材元数据设置帧数、帧尺寸、速度和循环。短动作通过播放结束回调恢复 idle，不自行用定时器重写逐帧播放器，不把图片宽度和帧数散落写死在组件里。

状态优先级和业务触发规则仍由项目代码维护，AnimatedSprite 不自动决定“留言成功应播放什么”。渲染器初始化或运行失败时，展示静态角色与 HTML 功能入口。

降低动态效果时取消浮动、跳跃和逐帧循环，用静态表情及提示文本保留语义。视觉反馈之外，重要结果通过可访问的状态区域播报。

## 6. 内容组件

### 话题卡片

标题、两行正文摘要、匿名称呼、发布时间、公开评论数。整张卡片可打开详情，独立按钮不能产生嵌套点击冲突。

### 发布表单

输入标签、字数提示、简短匿名说明、提交按钮、错误位置。校验失败定位到对应字段；提交期间保留文字并显示处理中。

### 留言卡片

正文、匿名称呼、时间、公开回复数，以及查看回复入口。删除入口只对作者显示，且仍需服务端鉴权。

### 信箱

“我的内容”包含内容类型、摘要、状态和查看/删除操作。“收到的回复”包含来源、可公开的摘要、时间和已读状态。

### 管理页面

审核队列与举报队列分开展示。审核可以通过或填写原因后拒绝；隐藏已公开内容时填写处理原因。管理操作完成后刷新状态，失败时不得乐观显示为已处理。

## 7. 页面状态

| 场景 | 展示与行为 |
| --- | --- |
| 初次加载 | 简单加载占位，避免持续大幅动画 |
| 没有内容 | 简短说明＋发布入口 |
| 请求失败 | 错误提示＋重试，保留原输入或已加载数据 |
| 图片失败 | 占位角色和文字入口，不阻塞业务 |
| 已提交待审核 | 明确提示，提供“查看我的内容”入口 |
| 内容不可见 | “内容不存在或暂不可访问”，不给出私有正文 |
| 触发频率限制 | 展示服务端返回的等待时间，防止反复无效提交 |
| 身份失效 | 保留输入，提示需重新建立访客身份，旧内容管理权不保证恢复 |

## 8. 移动端与无障碍

- 表单输入不被虚拟键盘或底部安全区遮挡。
- 窄屏内容区单列排列，正文不使用固定高度裁切。
- 场景热点用真实按钮承载，有名称、焦点样式和可点击面积。
- 装饰图对读屏隐藏；承载功能的角色或按钮具有可访问名称。
- 弹窗启用焦点管理，关闭后焦点返回触发入口；气泡不形成键盘陷阱。
- 文字、图标和状态不能只依赖颜色区分。
- 支持 `prefers-reduced-motion`；首次访问不自动播放声音。

## 9. 交互验收

确认角色状态切换可恢复、连续操作无累积、所有功能有文字入口；逐项验证直接访问路由、返回列表、输入失败重试、后台暂停、减少动态效果，以及 320px 宽屏幕下的完整操作路径。
