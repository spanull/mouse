# 像素小院产品需求

版本：0.1，需求草案。日期：2026-10-29。

## 1. 产品目标

提供一个轻松、有互动感的匿名内容空间。用户进入像素小院，通过点击角色和场景物件浏览话题、参与讨论或留下短消息。

核心体验是“角色有生命感，入口有趣，阅读和表达方便”。首版以移动端 H5 为主，桌面端也可使用。

## 2. 需求依据与待确认项

用户已明确要求：像素型角色、待机会动、点击有反馈、动作对应功能、匿名吃瓜、留言板，以及适合 AI 执行的需求和任务文档。

素材方案已确认：以 GPT Image 为主要素材来源，生成角色、场景、道具、表情和动作参考，经像素修整后用于项目。图片在开发阶段提前生成，用户访问和点击页面时不调用 GPT Image。

动画方案已确认：使用 PixiJS 渲染小院和角色，使用 AnimatedSprite 播放待机、点击及成功动作。React 负责帖子、留言、表单、信箱和可访问按钮，CSS 负责气泡、按钮与简单页面效果。精灵图仍是动作素材，PixiJS 负责播放与渲染，业务代码负责状态切换；首版不引入地图寻路或物理系统。

以下为用于编排任务的建议方案，正式实现相关功能前需确认；未确认不阻碍制作模拟数据原型。

| 决策 | 建议方案 | 对实现的影响 |
| --- | --- | --- |
| 产品形态 | 普通 H5＋像素场景＋内容面板 | 不需要地图寻路、物理系统或游戏引擎 |
| 吃瓜来源 | 用户主动发布文字话题 | 若需要外部聚合，另行确认来源、接口和使用权限 |
| 匿名方式 | 无需注册，对其他用户匿名，使用浏览器访客凭证 | 清除浏览器数据或更换设备后无法恢复管理权限 |
| 发布规则 | 试运营时，新话题、评论、留言和回复先审核后公开 | 需要有人负责审核，发布成功不等于已经公开 |
| 技术与部署 | Next.js＋TypeScript＋PostgreSQL，服务商待定 | 预算、地域、域名和数据库配置需另行确认 |

其他待确认：产品名称、主要受众、内容主题、像素角色形象与配色、GPT Image 使用渠道及美术预算。不默认面向未成年人，也不默认任何特定圈子或组织。尚未生成正式素材时，允许自制占位素材验证交互；素材替换不应影响业务逻辑。

## 3. 首版范围

### 3.1 必须实现

- 像素小院首页、一个可交互主角和三个功能入口。
- 主角待机动画、点击反馈、提交成功反馈，以及减少动态效果设置。
- 吃瓜话题列表、详情、匿名发帖、一级评论。
- 留言列表、匿名留言、一级回复。
- “我的信箱”：查看当前访客自己的内容及收到的回复。
- 访客身份识别、自己的内容删除、内容状态提示。
- 发布校验、审核、举报、基础频率限制和管理入口。
- 移动端适配、键盘操作支持、加载和错误状态。

### 3.2 首版不包含

账号注册、跨设备恢复、私聊、图片视频上传、外部自动抓取、复杂搜索、积分商城、排行榜、多人地图、自由行走、背景音乐。

点赞、表情反应、角色换装和随机事件属于后续功能，不作为首版完成条件。

## 4. 页面与用户流程

### 浏览与讨论

进入小院 → 点击吃瓜摊 → 浏览已公开话题 → 打开详情 → 查看评论 → 输入评论 → 提交审核 → 在自己的记录中查看状态。

### 发帖

进入吃瓜广场 → 点击发帖 → 输入标题与正文 → 校验 → 提交审核 → 获得明确反馈 → 在我的信箱查看；审核通过后出现在公开列表。

### 留言

点击留言牌 → 浏览公开留言 → 输入短消息 → 提交审核。打开某条留言后可查看和提交一级回复。

### 查看自己的内容

点击信箱 → 切换“我的内容”和“收到的回复” → 查看状态或跳转详情。自己的待审核和被拒绝内容仅本人及管理员可见。

## 5. 功能规则

### F01 像素首页

- 场景有主角、吃瓜摊、留言牌、信箱，入口始终显示文字标签。
- 点击主角播放短动作，并提供“去吃瓜”“去留言”两个操作。
- 场景加载失败时仍显示文字入口，不能因美术失败导致功能不可用。

### F02 吃瓜广场

- 只展示已公开、未删除的话题，按发布时间倒序排列。
- 列表展示标题、正文摘要、匿名称呼、发布时间和公开评论数量。
- 每页建议 20 条，使用“加载更多”；首版不提供复杂分类和热度算法。
- 详情展示完整正文、一级评论和评论入口。

### F03 发布与评论

- 建议话题标题 4～40 个字符，正文 10～2000 个字符。
- 评论建议 1～500 个字符；首尾空白不计入长度，不允许纯空白。
- 字数按 Unicode 码点计算，前后端规则保持一致。
- 首版仅支持纯文本，不接受 HTML 或用户提供的可执行内容。
- 提交期间禁用重复操作；失败保留当前输入并允许重试。
- 成功反馈使用“已提交，审核后公开”，不能显示“已公开”。
- 首版不支持编辑。用户可删除自己的内容后重新提交。

### F04 留言板

- 留言建议 1～300 个字符，回复建议 1～300 个字符。
- 留言与吃瓜话题分开显示，按发布时间倒序排列。
- 回复只支持一级；没有回复的回复，不形成无限嵌套。
- 空列表显示引导文案和发布入口。

### F05 匿名与个人记录

- 前台展示随机匿名称呼，不展示登录信息、凭证或内部访客标识。
- 同一浏览器有效凭证下的作者称呼保持一致；该规则会使公开内容可按称呼关联，需要在说明中告知。
- “匿名”表示对其他用户匿名，不承诺技术上的绝对不可追踪。
- 管理权限依赖浏览器凭证；清除数据、凭证过期或换设备后不保证恢复。
- 首次发布前用简短提示说明上述边界，不能仅依赖隐蔽的说明页面。
- 删除必须在服务端验证归属；其他访客无法读取自己的私有记录。

### F06 我的信箱

- “我的内容”汇总自己发布的话题、评论、留言和回复，展示审核状态。
- “收到的回复”展示其他访客对自己话题或留言的已公开回复，首版没有邮件或推送。
- 自己回复自己不生成通知；回复审核通过时才生成通知。
- 详情不可访问时显示“内容已不可用”，不泄露已隐藏正文。

### F07 管理与举报

- 每项公开内容支持举报，选择原因并可填写说明。
- 同一访客对同一项内容只保留一条待处理举报。
- 管理员可审核通过、拒绝、隐藏公开内容，并处理举报。
- 管理入口需要独立身份认证和服务端授权，不能只通过隐藏按钮保护。
- 举报不自动删除内容，由管理员决定；处理操作需留记录。
- 内容规则明确禁止泄露他人隐私、人身攻击及违法内容，提供举报入口。

## 6. 状态与可见性

| 状态 | 公开列表和详情 | 作者 | 管理员 |
| --- | --- | --- | --- |
| pending 待审核 | 不可见 | 可见及可删除 | 可见及可审核 |
| published 已公开 | 可见 | 可见及可删除 | 可见及可隐藏 |
| rejected 未通过 | 不可见 | 可见原因及可删除 | 可见 |
| hidden 已隐藏 | 不可见 | 仅见状态及处理原因，不回显正文 | 可见及可处理 |
| deleted 已删除 | 不可见 | 仅见删除状态，不回显正文 | 按保留策略处理 |

公开列表、详情、计数和通知预览都遵守相同的可见性规则。父话题或留言不可见时，其下回复也不可公开访问。

删除为逻辑删除：立即从业务展示中移除，不声称数据已从备份中立刻消失。正式上线前确定数据库和备份保留周期。

## 7. 非功能要求

- 页面在 320px 宽度下无横向滚动；桌面端居中展示。
- 触控入口不小于 44×44 CSS 像素，正文可读，不强制采用像素字体。
- 动画不阻塞输入、点击和导航；页面不可见时暂停非必要动画。
- 支持系统减少动态效果偏好，提供静态反馈替代。
- 图片加载失败、网络中断、重复提交、内容不存在、凭证失效均有明确状态。
- 发布时间由服务端生成；首版界面按 Asia/Shanghai 展示，并在完整时间处注明时区。
- 性能预算建议：首屏场景与角色素材总传输体积不超过 1 MB；该值是预算，不是已测得的指标。

## 8. 首版验收

- AC01：进入首页后可看到角色待机，所有功能入口均可点击及键盘访问。
- AC02：点击角色有即时反馈，连续点击不叠加失控的动画或面板。
- AC03：用户可浏览话题、打开详情、提交话题与评论，并看到正确审核状态。
- AC04：用户可留言及回复，一级回复边界有效。
- AC05：审核前内容不出现在他人的列表、详情、计数和通知中；通过后才公开。
- AC06：用户仅能管理自己的内容，不能伪造访客标识删除别人的内容。
- AC07：父内容隐藏或删除后，直接访问其回复也不能获取公开正文。
- AC08：发布失败保留输入，重试不会意外生成重复内容。
- AC09：信箱仅展示当前访客的记录；回复审核通过后产生一次通知。
- AC10：举报可提交，管理员可以审核和隐藏内容，普通访客无法调用管理接口。
- AC11：手机、小屏幕、桌面与减少动态效果模式均可完成主要流程。
- AC12：更换浏览器或清除凭证后的身份变化有说明，不错误承诺恢复能力。

## 9. 后续版本候选

表情互动、搜索分类、角色换装、节日场景、可选账号绑定与跨设备恢复。新增需求单独评估，不在首版中顺手实现。
