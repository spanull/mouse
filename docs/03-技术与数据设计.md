# 技术与数据设计

React＋PixiJS AnimatedSprite 的场景与动画方案已确认；服务端框架、数据库与部署仍为建议选型。实现前先阅读产品需求中的待确认项。

## 1. 技术路线与取舍

| 路线 | 优点 | 成本 | 首版建议 |
| --- | --- | --- | --- |
| React 页面＋PixiJS AnimatedSprite | 成熟的精灵动画、场景渲染和资源管理，业务页面独立 | 需要处理画布生命周期和 HTML 入口定位 | 已确认采用 |
| Phaser 等游戏引擎＋网页内容层 | 适合走动、碰撞、地图探索 | 资源加载、输入和页面状态协调更复杂 | 暂不采用 |
| React＋Motion | 适合图片浮动、按压反馈、面板过渡 | 不提供完整像素场景与精灵资源管理 | 当前用 CSS 处理简单界面效果，不额外引入 |
| Rive | 可视化制作交互动画与状态机 | 需要制作 Rive 动画文件，PNG 不能自动变成完整角色 | 不作为首版流程 |

推荐 Next.js＋TypeScript 构建页面与服务端接口，PixiJS 处理场景和角色动画，CSS Modules 处理 HTML 布局、按钮与气泡效果，PostgreSQL 持久化业务数据。数据库访问层可采用 Prisma，最终版本选用开发时仍受支持且互相兼容的稳定版本。

若使用 Supabase 托管数据库，仍由服务端执行本文的权限校验；管理密钥不能放入浏览器。若改成客户端直连数据库，必须重新设计并验证行级安全策略，不能直接沿用服务端方案。

使用 `pixi.js` 的 AnimatedSprite 承担逐帧播放，项目仅维护业务状态切换。React 集成可采用官方 `@pixi/react`；安装前核对 React、PixiJS 与适配层的兼容版本，并锁定依赖。若直接封装 PixiJS 实例，则由同一个封装负责完整生命周期，不同时维护两套场景实例。

组件拆成场景、角色动画、内容列表、表单、访客身份和管理模块；美术替换只修改资源配置与动画组件。

参考项目：[PixiJS](https://github.com/pixijs/pixijs)、[@pixi/react](https://github.com/pixijs/pixi-react)、[Phaser](https://github.com/phaserjs/phaser)、[Motion](https://github.com/motiondivision/motion)、[Rive Web Runtime](https://github.com/rive-app/rive-wasm)。若后续增加走动、碰撞与地图探索，再评估 Phaser，首版不并装多个渲染框架。

## 2. 建议目录

```text
src/
  app/                 页面与接口入口
  components/scene/    场景、热点、角色动画
  components/content/  列表、详情、表单、状态反馈
  lib/server/          数据库、身份、权限、限流、审核
  lib/validation/      前后端共用的输入规则
  types/               公共类型
public/assets/
  characters/          角色图与精灵图
  scene/               场景与物件
  ui/                  图标和装饰
assets-manifest.json   素材来源、授权与动画元数据
docs/                  当前需求、任务和部署说明
```

目录是建议，不要求为了符合目录示意而创建空模块。方法注释使用中文，说明用途、关键参数、返回值及边界行为。

## 3. 匿名身份

1. 用户首次需要发布或查看个人记录时，由服务端创建访客身份。
2. 使用密码学安全随机数生成不可预测的会话凭证，数据库只保存凭证摘要。
3. 通过 HttpOnly Cookie 交付凭证；生产环境启用 Secure、SameSite=Lax，限定 Path 和有效期。
4. 服务端从 Cookie 解析身份，不接受请求体中自报的作者 ID 作为授权依据。
5. 公开响应只包含匿名称呼和业务字段，不返回凭证摘要、内部访客 ID 或管理信息。

会话建议有效期 30 天并在有效访问时续期，最终期限需要确认。丢失或过期后不自动恢复旧身份；不使用浏览器指纹偷偷重建身份。

匿名会话可被主动重建，单靠会话限流不能抵御刷帖。公开上线前按部署环境增加共享限流存储和必要的网络层限制；网络信息的用途和保留期应明确，不能把所有原始请求无限期记录。

管理员身份与匿名身份分离，使用成熟身份认证方案。具体身份提供方及管理员名单在部署前确认，不自行实现明文密码登录。

## 4. 数据模型

所有主键由服务端生成。所有时间存储为 UTC，统一在展示层转换。

| 表 | 关键字段 | 约束与用途 |
| --- | --- | --- |
| visitors | id、display_name、created_at | 访客及随机称呼；称呼唯一，冲突时重试 |
| visitor_sessions | id、visitor_id、token_hash、expires_at | token_hash 唯一，保存摘要，不保存明文凭证 |
| topics | id、author_id、title、body、status、moderation_reason、created_at、published_at、deleted_at | 话题；公开排序使用 published_at |
| topic_comments | id、topic_id、author_id、body、status、moderation_reason、created_at、published_at、deleted_at | 仅一级评论，不设置 comment_parent_id |
| messages | id、author_id、body、status、moderation_reason、created_at、published_at、deleted_at | 留言板主留言 |
| message_replies | id、message_id、author_id、body、status、moderation_reason、created_at、published_at、deleted_at | 一级回复 |
| reports | id、reporter_id、target_type、target_id、reason、details、status、created_at、resolved_at | 举报对象由服务端按类型检查；同对象同访客仅一条 open 记录 |
| notifications | id、recipient_id、source_type、source_id、read_at、created_at | source_type 为评论或留言回复；接收者＋来源类型＋来源 ID 唯一 |
| moderation_logs | id、admin_id、target_type、target_id、action、reason、created_at | 记录审核、拒绝、隐藏和举报处理 |
| submission_keys | visitor_id、operation、client_request_id、payload_hash、resource_id、created_at | 访客＋操作＋请求标识唯一，用于创建内容幂等 |

内容 status 限定为 pending、published、rejected、hidden、deleted。举报 status 限定为 open、resolved、dismissed。

跨表 target_type/target_id 不能只依赖字符串存在：服务层限制合法类型并检查目标；若数据库实现采用可空外键，应增加“仅一个目标非空”的约束。

为公开列表的 status/published_at/id、作者记录的 author_id/created_at/id、回复的父 ID/status/published_at/id 和通知的 recipient_id/created_at/id 建索引。

## 5. 状态流转和权限

- 创建内容：进入 pending。
- 管理员审核：pending → published 或 rejected。
- 管理员隐藏：published → hidden。
- 作者删除：pending/published/rejected/hidden → deleted。
- deleted 为业务终态，重复删除返回成功，不重新发布。
- 首版不提供 rejected/hidden 的重新公开操作，避免隐含的通知和内容恢复规则。

审核状态更新、审计记录、必要通知应在同一事务中提交；并发审核采用条件更新，只有首次合法流转成功。

发布评论或回复时，父对象必须已公开且未删除。审核回复通过时重新检查父对象；父内容已不可见时拒绝通过并提示管理员。

父内容后续被隐藏或删除时，不必批量改写每条回复状态，但所有公开查询必须检查父对象可见性。隐藏或删除后的内容不得出现在计数、公开摘要、通知预览和直接详情中。

通知读取时动态检查来源与父对象是否可见；不可见时只展示“内容已不可用”。通知不复制存储正文，避免隐藏后泄露旧副本。

## 6. 接口建议

| 方法与路径 | 功能 | 权限 |
| --- | --- | --- |
| POST `/api/visitor-session` | 建立访客会话，已有有效会话则复用 | 公开，限流 |
| GET `/api/topics` | 公开话题分页 | 公开 |
| POST `/api/topics` | 创建待审核话题 | 有效访客 |
| GET `/api/topics/:id` | 公开话题详情 | 公开，仅公开可见内容 |
| GET/POST `/api/topics/:id/comments` | 评论分页/提交 | 读取公开，写入有效访客 |
| GET/POST `/api/messages` | 留言分页/提交 | 读取公开，写入有效访客 |
| GET `/api/messages/:id` | 留言详情 | 公开，仅公开可见内容 |
| GET/POST `/api/messages/:id/replies` | 回复分页/提交 | 读取公开，写入有效访客 |
| GET `/api/me/content` | 自己的内容及状态 | 当前访客 |
| GET `/api/me/content/:type/:id` | 自己的私有内容详情 | 当前访客，按状态过滤正文 |
| DELETE `/api/me/content/:type/:id` | 删除自己的内容 | 当前访客，验证归属 |
| GET `/api/me/notifications` | 收到的回复 | 当前访客 |
| PATCH `/api/me/notifications/:id` | 标记已读 | 当前访客，验证归属 |
| POST `/api/reports` | 举报公开内容 | 有效访客 |
| GET `/api/admin/content` | 审核队列及状态筛选 | 管理员 |
| PATCH `/api/admin/content/:type/:id` | 审核或隐藏 | 管理员 |
| GET `/api/admin/reports` | 举报队列 | 管理员 |
| PATCH `/api/admin/reports/:id` | 处理举报 | 管理员 |

列表返回 items、nextCursor。游标使用排序时间＋ID，限制单次条数，避免相同时间造成漏项或重复。公开列表按发布时间倒序，个人记录按创建时间倒序。

错误统一包含 code、message、fieldErrors（可选）、retryAfterSeconds（可选）。区分 400 输入错误、401 身份失效、403 无权限、404 不可访问、409 状态或幂等冲突、429 频率限制、500 服务端故障；对无权查看的内容避免暴露其是否存在。

公开接口不因作者身份额外返回待审核正文，私有内容只从 `/api/me` 读取，以降低共享缓存泄露风险。

## 7. 输入、重试与频率限制

- 输入长度与纯文本规则在客户端提示、服务端再次验证；React 文本渲染，不使用未经处理的 HTML 注入。
- 创建请求携带 clientRequestId，同一次提交的网络重试复用该值。
- 使用事务和唯一约束确保幂等：相同请求标识和相同正文返回已有结果；相同标识但不同正文返回 409。
- 用户修改输入后新建请求标识；幂等检查应先于新增内容配额扣减。
- 建议初始限额：每访客每小时 5 个话题；评论、留言与回复合计每分钟 5 条；举报每小时 10 次。
- 限额为可配置建议值，需结合实际运营调整；响应说明可重试时间。
- 所有 Cookie 鉴权写接口实施 CSRF 防护，例如同源 Origin 校验；跨域策略默认关闭。
- 私有和管理响应禁用共享缓存。待审核内容不可通过预渲染、缓存或日志意外公开。

## 8. 素材与动画接入

素材制作流程：GPT Image 生成 → 像素编辑工具修整、裁切与对齐 → 导出 PNG 和动画元数据 → 保存到 `public/assets/` → PixiJS 加载纹理 → AnimatedSprite 播放动作 → React 展示业务页面。

GPT Image 用于开发阶段制作素材，不属于 H5 的运行时依赖。首页加载、点击角色和提交留言均不触发图片生成请求，不需要在浏览器或生产应用中配置图片生成密钥。若选择 API 制作素材，密钥仅用于受保护的制作环境，费用发生在生成和迭代阶段。

先用静态 Sprite 和 ticker 实现浮动及点击短跳，以占位帧验证 AnimatedSprite，再接入经检查的正式动作帧，实现真正的眨眼、挥手等动作。资源清单记录生成模型（若可获取）、提示词文件、参考图及后期处理过程，详细要求见 [AI 提示词与素材规范](05-AI提示词与素材规范.md)。

资源元数据记录图片路径、单帧尺寸、帧数、帧率、是否循环、脚底锚点和静态降级帧。角色组件只接收状态与资源配置，不执行发帖或审核请求。

网络提交由 React 业务层处理，成功或失败后向场景传入反馈状态；动画完成不改变请求结果。idle 循环播放，pressed/success 单次播放，完成后恢复 idle；error 缺少独立动作帧时使用静态表情与 HTML 提示。

### 8.1 资源适配与播放

- `assets-manifest.json` 是项目自定义资源清单，不是可直接传给 PixiJS Spritesheet 的图集格式。首版按帧尺寸和帧数裁出有序纹理列表，再交给 AnimatedSprite；如果使用图集 JSON，先转换成当前 PixiJS 版本支持的格式。
- 将清单中的 fps 明确映射到播放器速度或每帧时长，不将 fps 数值直接当成 animationSpeed。按所选版本文档实现，并检查实际播放时长。
- 清单锚点以像素表示，映射到 PixiJS anchor 时除以对应帧宽高；不得直接将 (32, 56) 当成归一化 anchor。
- 使用最近邻纹理采样并保持像素网格对齐；CSS `image-rendering` 不能替代画布内部纹理采样设置。
- 使用 AnimatedSprite 的循环、播放/停止和完成回调控制动作，不用 setInterval 重写逐帧计时。统一使用一个更新来源，避免自动更新与手动 ticker 重复驱动。
- 动作切换时解除旧回调或校验当前状态，防止被中断动作的结束回调覆盖新的动作。检查首帧、末帧及循环边界，没有空白帧。

### 8.2 React 集成和生命周期

- 场景在浏览器端初始化；如果采用 Next.js，使用客户端组件边界，必要时动态加载，服务端渲染阶段不访问 window、document 或创建渲染器。
- 业务列表、表单和文字提示保留为 HTML；画布和可访问按钮使用统一布局坐标与事件入口，不在 Canvas 中实现文本输入框。
- 每个挂载中的场景只创建一个应用实例。处理 React 开发模式下重复挂载、异步初始化期间卸载、路由离开和重新进入，避免遗留画布、监听器或 ticker。
- 页面不可见时暂停装饰动画，恢复可见后按当前状态播放；减少动态效果时停在静态帧，HTML 提示继续提供反馈。
- 卸载时释放当前场景拥有的实例、监听和资源；共享纹理采用明确的所有权或缓存策略，不能销毁其他组件仍在使用的资源。
- 渲染器不可用、资源失败或上下文丢失时保留静态角色与 HTML 入口，并提供合理的重试方式。

## 9. 部署与运行

- 原型阶段使用确定性模拟数据，明显标注演示模式。
- 生产阶段配置应用域名、数据库、管理员身份服务和共享限流存储。
- 环境变量区分服务端密钥与公开配置；只提交占位示例，不提交真实凭证。
- 提供数据库迁移和本地启动说明；种子演示数据不得自动写入正式库。
- 首次部署先验证匿名发布、审核公开、跨访客权限和删除流程，再开放入口。
- 正式上线前确定运营负责人、素材授权、数据与备份保留期、部署预算；域名、付费服务和正式发布由用户选择。

## 10. 验证重点

自动化验证优先覆盖身份归属、审核可见性、父子内容隐藏、并发审核通知去重、提交幂等和输入边界。动画和排版以实际浏览器操作检查为主，不为静态装饰添加机械的实现镜像测试。不要求执行 lint 命令。
