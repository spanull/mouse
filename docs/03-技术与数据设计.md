2026-11-03 部署补充：用户选择由宝塔部署当前演示版，沿用 Next.js Node.js 服务和 sessionStorage，不扩展为共享后端。目标服务器上安装并构建，Nginx 代理本机端口并提供 HTTPS；操作与真实部署状态见 [宝塔部署说明](11-宝塔演示版部署.md)。

## 1. 当前技术

Next.js 16.4.3、React 19.3.1、TypeScript 5.9.3、PixiJS 8.22.0。依赖以 package-lock.json 为准。使用直接封装 PixiJS，不同时安装 @pixi/react 或游戏引擎。

- React：路由、菜单、表单、评价、场景热点、便利贴及可访问弹窗。
- PixiJS AnimatedSprite：访客鼠自然眨眼／挥手、鼹鼠服务动作和厨师工作；每类按独立帧配置播放。
- PNG＋CSS：之家、餐厅、酒吧、标牌、饮品和短过渡。
- sessionStorage：本标签页演示内容、匿名身份、钱包、评价和举报。
- 无数据库、真实管理员认证、实时消息服务或 AI 审核调用。

Flutter、UniApp、NestJS、Go、独立 Node 服务是用户文档中的后续技术候选，不是本轮迁移要求。没有强社交或实时聊天，不引入 WebSocket / Socket.IO。

## 3. 本地模型

- `DemoState.version = 2`，存储键 `mouse-world-v2`。
- `profile`：匿名 id、name、avatar、可选 identity；首次浏览器初始化用 crypto.randomUUID，换鼠种不换身份。
- `entries`：kind 仅 `dish / whisper`，包含 title、teaser、body、category、truth、spice、drink、作者、鼠种、status、createdAt、reason、rewarded。
- `wallet`：北京时间 day、coins、三个时段的 meals、bonus 加餐券、drinks。
- `tasted`：已解锁菜品 ID 集合，跨日保留。
- `ratings`：菜品 ID → 当前鼠鼠的五档单票评价。
- `reports`：内容 ID 与原因，本标签页去重。

旧 `mouse-demo-v1` 不读取、不清除、不自动迁移。旧版话题／评论数据不会伪装为新菜品。

快照恢复检查版本、必需字段、枚举、时间、非负安全整数和次数范围，损坏时提示并使用新的演示数据。

## 4. 额度、状态与幂等

### 品尝

`refreshDay` 按北京时间重置日期；`tasteDish` 依次检查内容公开、是否已解锁／自己作品、金币、餐次和加餐券。基础次数优先使用，用完再消耗加餐券。扣金币、扣机会和写入 tasted 在同一状态对象中完成。

Provider 每秒、聚焦与页面可见性变化时同步展示时钟；实际消费操作再次使用当前时间，不依赖定时器精确触发。

### 提交

创建先查请求标识再验额度。同 ID 同载荷返回已有结果；同 ID 不同载荷拒绝。失败和取消不写入内容或扣次数。树洞成功提交与 drinks 加一同一次更新。菜品提交不扣用餐次数。

### 审核奖励

`pending → published/rejected`，`published → hidden`，作者可收起为 `deleted`。首次通过自己的菜品才把 rewarded 标为 true，并增加 1 金币与 1 加餐券。重复审核失败，树洞不奖励；隐藏和删除不重新奖励也不退款。后续不支持自动重发审核奖励。

### 评价

只允许已品尝的公开菜品，不能自评。以菜品 ID 为键覆盖选择，等价于每访客／每菜一票。前端不提供文字评论输入。

### 可见性

所有公共展示只接受 published。作者私有详情必须检查归属，hidden/deleted 不回显正文。气泡、墙面、菜单、举报和评价使用同一公开规则。

**演示限制：** 种子和待审数据仍存在浏览器状态中，UI 的私有过滤与正文解锁不是安全隔离。不能将客户端限制当作反作弊或生产付费保护。

## 5. 正式服务建议模型（待实施）

建议 PostgreSQL＋成熟迁移工具；服务框架和托管提供商待确认。

| 表 | 字段与约束 |
| --- | --- |
| visitors / sessions | 匿名访客、随机称呼、角色、可选私有描述；只存会话摘要，HttpOnly/Secure/SameSite Cookie |
| dishes | 作者、标题、独立简介、正文、分类、辣度、盐味、审核状态、发布时间 |
| whispers | 作者、饮品类型、正文、状态、发布时间 |
| daily_wallets | visitor_id＋北京时间日期唯一，金币与三餐消费、点酒消费计数 |
| bonus_credits | 访客的额外机会余额或账本，跨日保留 |
| dish_unlocks | visitor_id＋dish_id 唯一，首次解锁事务写入 |
| ratings | visitor_id＋dish_id 唯一，值只能是五档枚举 |
| reward_ledger | dish_id＋reward_type 唯一，审核通过一次发奖 |
| submission_keys | visitor_id＋operation＋client_request_id 唯一，保存 payload_hash 和 resource_id |
| reports | 访客、目标类型／ID、原因、状态；同对象同访客 open 举报唯一 |
| moderation_logs | 管理员、目标、操作、原因、时间 |

不建评论表、回复表、好友表、私信表或回复通知表。个人作品通过菜品和心声查询聚合。

### 正式服务事务要求

- 服务端生成时间与作者 ID，不接受浏览器自报身份、余额或奖励标记。
- 同时请求不同菜品时锁定钱包行或用条件更新，禁止余额和次数超扣。
- 解锁唯一约束先防重复，同一菜品并发请求仅扣一次。
- 发布幂等检查在点酒次数扣减之前；同标识不同载荷返回 409。
- 审核状态更新、奖励账本、余额与审计日志同一事务提交。
- 午夜按服务端 Asia/Shanghai 日期查询或创建每日钱包；不是定时任务累加金币。
- 菜品正文未解锁时不发送到客户端，公共菜单仅返回 title/teaser/tags；已解锁内容被隐藏后同样禁止读取。
- 私有和管理响应禁用共享缓存，CSRF 防护和跨访客权限由服务端执行。

## 7. 审核与限流

当前 validateDraft 只有长度、枚举和明显联系方式检测。真实人名、地址、学校公司、政治和网暴分类待服务端 AI 审核接入。审核服务异常时保持 pending，不自动公开。风险边界不靠客户端正则兜底。

除游戏消费额度外，生产需要额外防滥用限流；“厨房奖励”不能无限刷取。内容重复检测、发布速率、举报限额和奖励反作弊阈值在后端阶段按运营规则确定。本轮不虚构已实现。

## 8. 动画与素材

角色帧使用统一画布和脚底锚点，横排真实 Alpha PNG，最近邻采样。旧 4／4／6 帧及位移补帧方案已被用户否定，新自然动作按资源清单独立配置帧数与停留时间。AnimatedSprite 关闭 autoUpdate，由单一 app.ticker 更新；短动作结束回 idle，不积压点击。

PNG 与 CSS 场景独立于业务数据。正式 GPT Image 素材仍是开发期产物，访问页面不调用图片服务。清单来源、参考图、修整记录和原型替代见素材文档。

## 9. 验证

数据测试覆盖时段边界、午夜、重复消费、金币不足、奖励去重、加餐券、点酒幂等、删除不退款、输入边界和隐藏可见性。浏览器覆盖两店流程、单页菜单、评价、厨房审核、酒吧送酒、角色恢复、减少动态效果、资源失败和小屏。

真实权限、并发事务、审核服务、跨访客共享与真机性能必须在后端及正式素材接入后另验收。不执行 lint。

## 10. 成熟自适应方案

采用 CSS picture 横竖构图切换、object-fit: cover、ResizeObserver 与九宫格。背景图片宽高为 Bw/Bh，场景为 W/H：s=max(W/Bw,H/Bh)，图像尺寸 (Bw*s,Bh*s)，偏移 ((W-Bw*s)/2,(H-Bh*s)/2)。世界物件使用同一比例和偏移，入口按视口安全区布局；所有鼠鼠、图标等比例缩放。

面板使用 CSS border-image-slice（九宫格），四角保持形状，边缘重复，中间填充；不对整张面板使用 100% 100% 拉伸。Canvas 中对应成熟方案是 PixiJS NineSliceSprite，本项目面板包含原生表单，使用 CSS 方案保留无障碍。

ResizePlugin 能适配画布尺寸，但不会自动保证场景构图与热区正确；pixi-viewport 适合可拖拽缩放的大地图，本项目固定小场景无须额外引入。资料及对比见 10。

开发输出目录 `.next-dev` 与生产 `.next` 分离，避免构建破坏正在运行的开发预览。


### 场景与人物独立动效补充

每个场景包含独立环境动效：之家仅保留融合背景的松鼠停留后爬走（动态叶片／灯光已取消），餐厅灯火／植物／锅边热气，酒吧灯光／植物／客鼠活动。五鼠种分别有待机眨眼、挥手和个性闲暇动作（花枝鼠看地图、仓鼠嗑瓜子、田鼠闻花、龙猫理毛、睡鼠打哈欠）；厨师有搅拌、尝味、招呼；客鼠有眨眼与喝酒／打哈欠；鼹鼠保留八类独立动作。

环境与角色分层播放，间歇错峰，交互动作优先于自动闲暇，不进行整体抖动。减少动态效果和隐藏页面时暂停。动作素材仍全部来自指定接口，具体帧数、触发规则和验收见 [游戏UI与自适应验收](10-游戏UI与自适应验收.md)。

## 自然动作运行配置

`public/assets/natural/manifest.json`登记角色每动作的file、frameCount、durations和loop。角色帧192方形，厨师／坐姿客鼠／松鼠为256方形。PixiJS FrameObject保留每帧毫秒时长，自动闲暇只在无手动／服务动作时触发。环境由`src/components/scene/ambient-life.tsx`使用Web Animations离散背景位置播放，不增加Canvas，不自行绘制图像。

`prepare-natural-assets.mjs`从原图检测透明网格分隔、统一来源尺度、去色键、切帧及固定家具下部；全部原始图案仍来自接口。导出后清单重置待复验。

## 2026-11-02 播放器恢复修正

MouseActor以`action.once`和`onActionComplete`驱动受控服务。完成事件同时核对动作与令牌；受控动作禁用循环，末帧等待下一个动作，普通互动仍正常回待机。BarScene移除2200/4400/6600毫秒的固定步骤定时器。动作图并行加载，`Promise.allSettled`收齐结果后统一初始化或释放；卸载后不再创建帧纹理。

`visibilitychange`暂停Pixi ticker并保留帧进度；系统静态偏好通过媒体查询change事件实时同步。对白只累计可见时间，送酒CSS动画同步暂停。素材加载失败／WebGL丢失通过错误回调切到有明确反馈的静态流程，不改动已有消费记录。环境短暂停留仅改变运行时duration，不改变清单帧数或素材来源。

## 2026-11-02 首页逐页修正（优先于此前环境动效要求）

首页取消单独叠加的动态柳枝／叶片和灯笼，保留背景原画；餐厅、酒吧暂不改版。松鼠须直接参考首页横竖背景的细像素纹理、光照、轮廓和景深，作为小型环境访客融入右侧植被，不能贴一个粗描边大树干在场景上。

所有未来素材生成必须明确：画布与网格尺寸、场景中的显示尺寸、像素密度、镜头／透视、光源、留白和安全区。角色还要明确待机母版、身体高度、头宽／头身比、脚底中点与基线；所有动作参考同一母版。抬手、拿道具只改变动作包围盒，不能改变身体大小。背景／图标／道具／九宫格也必须约束比例、视觉尺寸、边框厚度和风格，禁止生成时自动紧裁或随动作缩放。

跨动作验收必须比较“待机→挥手→闲暇→待机”实际像素和场景播放，不能用相同Canvas大小或文件分辨率替代。导出用身体／脚底基准对齐，不按包含尾巴、手和道具的每帧外接框居中。整组允许一次等比例规格归一；禁止逐帧缩放修饰模型变形，不合格需重做。已有成功原图的历史提示词保持原样，不倒填新约束。

首页增量导出：`node scripts/prepare-home-assets.mjs`，输出版本化home-v3图片并只更新五种首页角色及松鼠。历史全量导出会覆盖清单，因此应随后执行首页增量导出并重新检查，不得仅运行旧脚本交付。尺寸测量写入`art-source/review/home-v3/geometry.json`；全动作共用192×192透明画布和脚底锚点。

### 首页松鼠入场补充（2026-11-02）

来访者必须包含“隐藏→露鼻／探头→前爪伸出→身体爬出→坐稳→离开→完全隐藏”的真实连续姿势；首次加载和循环边界均从隐藏状态开始。禁止隐藏帧直接切到完整站姿，也不能用倒放离场、淡入、缩放或平移同帧替代入场。全循环保持主体尺寸、枝条与遮挡叶片一致，优先同一张图生成；分图拼接必须检查两个接缝。隐藏页面暂停，减少动态效果保持隐藏状态。
