# AI 提示词与素材规范

本文提供素材制作流程与提示词，不代表已经生成或购买素材。已确定以 GPT Image 为主要素材来源；美术风格、角色形象、具体生成渠道与预算仍需确认。

## 1. 首版制作策略

采用“GPT Image → Aseprite 修整与制作动作 → 自动导出 PNG 和配置 → PixiJS 播放”的素材生产流程。先生成角色静态定稿，经修整后接入 PixiJS Sprite 完成原型；简单动作在定稿上修改像素，复杂姿势可再由 GPT Image 提供参考，最终使用 AnimatedSprite 播放。正式素材未到位时可用自制占位图推进交互。

素材在开发阶段提前生成并保存到项目中。用户浏览页面、点击角色或提交留言时，只加载静态图片并运行前端动画，不调用 GPT Image，也不会因这些操作产生图片生成费用。

- 静态 Sprite 可通过位移、缩放和旋转呈现微动，不能凭空生成真实的眨眼和挥手姿势；CSS 用于 HTML 按钮、气泡和页面效果。
- 精灵图保存多张同尺寸姿势帧，PixiJS AnimatedSprite 负责逐帧播放，业务代码负责动作状态切换。成熟播放器仍需要经修整的动作素材。
- 分层骨骼动画要求拆分身体部件，首版不采用，避免增加美术和适配成本。

## 2. 素材来源

GPT Image 是主要制作来源；现成素材库、自绘和委托画师作为补充或修整方案，不要求购买素材包才能开发。角色、道具、背景分别生成，保持统一色板、视角和像素颗粒。

| 来源 | 推荐用途 | 采用前检查 |
| --- | --- | --- |
| GPT Image（主要来源） | 角色定稿、场景背景、独立道具、表情及动作参考 | 生成渠道与适用条款、参考图来源、透明背景、角色一致性和最终尺寸 |
| [itch.io](https://itch.io/game-assets) | 成套角色和场景包 | 单个素材包的许可、商用、修改和署名条件 |
| [Kenney](https://kenney.nl/assets) | 原型道具和 UI 资源 | 具体资源包的许可与风格适配 |
| [OpenGameArt](https://opengameart.org/) | 像素角色、场景和动画参考 | 作者署名、许可版本、衍生作品约束 |
| 自绘或委托画师 | 核心角色和正式动作 | 使用范围、源文件、修改权和交付尺寸 |

上表明确了主要来源和备选来源，不代表对具体素材授权的确认。生成素材记录所用服务、提示词、参考图和适用条款；外部素材记录资源页面、作者、许可证原文或随包文件与所需署名。免费不等于可以任意商用或再次分发。

不要直接使用他人游戏中的知名角色、截图切图或来源不明的图片作为正式资源。

## 3. 工具与流程

| 工具 | 职责 | 项目中的选择 |
| --- | --- | --- |
| GPT Image | 角色定稿、场景、道具、表情与动作关键姿势 | 主要出图来源；不假定能直接输出 64×64 像素成品 |
| [Aseprite](https://www.aseprite.org/) | 像素修整、图层、洋葱皮、逐帧动画、动作标签和批量导出 | 首选编辑器；官方成品软件付费，执行前检查本机安装和适用许可 |
| [LibreSprite](https://github.com/LibreSprite/LibreSprite) | 免费开源的像素绘制与动画编辑 | 无可用 Aseprite 时的备选，单独验证导出与自动化能力，不假定兼容所有 Aseprite 参数 |
| [Piskel](https://github.com/piskelapp/piskel) | 浏览器内像素绘制和简单动画 | 少量素材快速编辑的备选，不作为默认自动化导出链路 |
| [TexturePacker](https://www.codeandweb.com/texturepacker) | 多张图片打包为纹理图集及 JSON | 素材量增大时考虑；选择 PixiJS 导出格式，使用前核对所需功能和许可 |
| [Free Texture Packer](https://github.com/odrick/free-tex-packer) | 开源图集打包 | 免费备选；更新较久，先验证当前 PixiJS 兼容性再采用 |

首版采用 GPT Image 和一个像素编辑器即可，不要求同时安装全部工具。选择这条流程不代表软件已经安装、获得付费许可或素材已经生成。

流程：确定风格 → GPT Image 生成角色静态定稿 → Aseprite 修像素并制作动作 → 洋葱皮与循环预览 → 自动导出 PNG 和元数据 → 适配项目动画配置 → 保存至项目 `public/assets/` → PixiJS 接入 → 手机实测。

GPT Image 输出仍需检查帧数错误、格子偏移、肢体变化和假透明背景。没有通过检查时，不能仅因为“看起来像精灵图”就投入使用。参考图有助于统一形象，但不能保证每次生成完全一致。

### 3.1 具体制作步骤

1. 生成一个主角静态方案，确认轮廓、配色、服装和视角后保存定稿，后续动作使用该定稿作为参考。
2. 分别生成小院背景、吃瓜摊、留言牌、信箱和表情，保持同一风格；背景不包含角色和功能文字。
3. 对角色和物件进行裁切、透明背景处理、色板整理和尺寸统一；缩小到目标像素尺寸后检查轮廓，不将缩放视为自动完成像素美术。
4. 先将静态主角接入 PixiJS Sprite，通过 ticker 驱动微动和短跳，验证与 React 功能入口的交互；正式动作通过 AnimatedSprite 接入。
5. 在同一个角色源文件中制作动作并设置标签。眨眼、呼吸等简单动作优先复制定稿帧后修改少量像素；举手、吃瓜等姿势变化可由 GPT Image 提供参考，再在 Aseprite 中补帧、修整和对齐，不要求重新生成每一帧。
6. 记录最终提示词、参考图、可获取的模型信息和后期处理，更新资源清单，检查移动端显示和动画循环。

### 3.2 生成渠道与能力边界

- 可通过支持 GPT Image 的图像生成界面或 API 制作素材，具体渠道在执行 T04 前确定；本需求不绑定某一模型版本。
- 若通过 API 制作，使用受保护的制作环境保存密钥，不放入前端代码或公开资源目录。实际调用能力、额度和费用以该渠道为准。
- 角色和物件最终交付真实 Alpha 透明 PNG；所选模型或渠道不支持透明输出时，增加背景移除与边缘检查步骤，不能将棋盘格当成透明。
- 图片生成交付的是图像，待机、点击和业务反馈由前端动画状态机控制；不依赖生成模型输出可执行交互或完整动画文件。
- OpenAI 官方文档说明，多次生成的角色一致性和精确布局仍存在局限，精灵图需要逐帧验收。参考：[官方图像生成文档](https://developers.openai.com/api/docs/guides/image-generation)。

### 3.3 动作制作与可编辑源文件

保留 `art-source/characters/hero.aseprite` 作为角色可编辑源文件；使用其他编辑器时保存其可编辑项目，不仅保留合并后的 PNG。源文件中使用同一色板、画布、脚底基准和一致的图层组织。洋葱皮用于叠加查看前后帧，检查轮廓、位置和肢体衔接。

| 动作标签 | 首版内容 | 制作方法 | 运行规则 |
| --- | --- | --- | --- |
| idle | 呼吸、眨眼 | 复制定稿，微调身体和眼睛像素 | 循环 |
| pressed | 下蹲、跳起、落地 | 修改已有姿势，统一落地基准 | 单次，结束回到 idle |
| success | 开心、举手 | 使用定稿或 AI 关键姿势，修整并补帧 | 单次，结束回到 idle |

标签范围、帧顺序和帧时长在编辑器中明确设置。首版标签使用正向播放，每个动作内部采用统一帧时长，与资源清单中的 fps 对应。不同动作可使用不同速度。若后续需要不等帧时长，先扩展项目元数据和播放器适配，不能导出时悄悄丢弃时长。

成熟工具链可自动执行导出、格式转换与校验，但不保证提示词一次生成的角色和动作直接可用。风格确认、动作自然度和像素边缘仍需视觉检查。

### 3.4 自动导出与 PixiJS 适配

```text
GPT Image 角色定稿与姿势参考
                ↓
hero.aseprite：图层＋idle/pressed/success 标签
                ↓ Aseprite CLI 批量导出
PNG＋JSON：帧矩形、顺序、时长、动作标签
                ↓ 项目导出脚本转换与校验
hero-idle.png / hero-pressed.png / hero-success.png
＋ assets-manifest.json 中的运行配置
                ↓
PixiJS 有序纹理帧 → AnimatedSprite
```

- Aseprite 官方 CLI 提供批处理、`--sheet`、`--data` 和 `--list-tags` 等能力，可把图像和标签导出为文件。实际命令按已安装版本核对，不在文档阶段假定本机命令可用。
- T04 提供一个项目内可重复执行的导出入口，记录编辑器版本、源文件、导出参数和输出路径。源文件是编辑来源，PNG 和运行配置由它导出，避免人工分别修改导致不一致。
- 首版最终产物仍遵守第 4、5 节：每个动作一张水平排列、无裁边、无旋转、零间距、同尺寸帧的图片。导出入口可按标签直接输出，或读取中间 PNG/JSON 后整理为该格式。
- Aseprite 的 `meta.frameTags`、帧矩形和 duration 需转换为项目的动作配置，不将 Aseprite JSON、项目资源清单和 PixiJS 图集 JSON 当作同一种格式。
- 导出检查标签是否齐全、帧范围是否有效、帧数与尺寸是否一致、duration 是否为正及是否满足统一时长。由时长计算 fps；不要四舍五入后改变动作节奏。
- 先输出到中间目录，通过校验后再更新运行资源；失败不覆盖上一份有效资源。更新清单时保留来源、授权、提示词和生成记录，不能用导出结果清空人工登记字段。
- 用户修改角色源文件后，应能重复运行导出入口并在 PixiJS 预览中看到更新；应用启动和正式部署使用已导出的文件，不要求服务器安装 Aseprite。

参考：[Aseprite CLI 官方文档](https://www.aseprite.org/docs/cli/)。

### 3.5 何时引入图集打包工具

首版角色和场景数量较少，使用 Aseprite 导出即可。素材增多、需要统一图集或压缩透明空间时，再评估 TexturePacker；它负责整理已有图片，不负责生成角色或补齐动作。

采用图集后，使用 PixiJS 兼容格式和元数据加载纹理，同时调整运行资源清单与加载器。若启用裁边、旋转或打包间距，必须正确使用偏移、原始尺寸、旋转等信息，不能继续按等宽横排切帧。小院角色重点检查锚点和动作切换时的位置稳定性。

参考：[TexturePacker 与 PixiJS 官方教程](https://www.codeandweb.com/texturepacker/tutorials/how-to-create-sprite-sheets-and-animations-with-pixijs)。Free Texture Packer 是可替换的打包工具，不能未经验证直接沿用另一工具的配置。

## 4. 统一美术规范

以下为建议基线，正式生产前锁定：

| 项目 | 建议 |
| --- | --- |
| 视角 | 正面或轻微俯视，角色和场景物件统一 |
| 角色画布 | 每帧 64×64 像素 |
| 场景基础网格 | 16×16 像素，物件按整数网格构建 |
| 色板 | 全场景共享约 16～24 个主色，可按需要扩展 |
| 轮廓 | 统一深色描边，不混用多种粗细和光照 |
| 背景 | 角色及独立物件使用真实 Alpha 透明 PNG |
| 帧排列 | 每种动作独立图片，单行从左到右排列 |
| 帧间隔 | 0 像素，外边距 0 像素 |
| 锚点 | 64×64 角色建议脚底基准点为 (32, 56) |
| 放大 | 角色优先整数倍放大，PixiJS 纹理设为最近邻采样；HTML 降级图片使用 pixelated |

锚点是对齐基准，不要求跳跃时脚始终落在同一像素。非预期的位置抖动必须修正；原地动作应围绕共同基线制作。角色阴影建议单独一层，以便跳跃时仍留在地面。

像素风提示词不保证工具原生输出低分辨率像素图。较大图缩成 64×64 后需要重新检查轮廓、色板和细节，不能把缩小操作当成自动完成像素美术。

## 6. 素材登记格式

在项目根目录维护 assets-manifest.json。每项资源记录 assetId、file、sourceUrl、author、license、licenseEvidence、attribution、modified、approvalStatus，以及适用的动画字段。

此清单是项目自定义格式。接入时按 frameWidth、frameHeight、frameCount 生成有序纹理帧，再交给 AnimatedSprite，不能直接作为 PixiJS Spritesheet 图集 JSON 加载。fps 是每秒帧数，anchorX/anchorY 是像素坐标，需分别适配播放器速度与归一化锚点；具体要求见 [技术与数据设计](03-技术与数据设计.md)。

GPT Image 素材额外记录 generation：provider、model（无法获取时为 null）、channel、generatedAt、promptFile、referenceFiles 和 postProcessing。提示词和来源说明可保存在 `docs/assets/`，原始图可保存在 `art-source/`，只有最终运行素材放入 `public/assets/`。这些目录在实际制作时创建，不要求现在放置空文件。

示例仅描述格式，其中路径和授权状态都需要替换为真实值：

```json
{
  "assetId": "hero-idle",
  "file": "/assets/characters/hero-idle.png",
  "sourceUrl": null,
  "author": "待填写",
  "license": "待确认",
  "licenseEvidence": null,
  "attribution": null,
  "modified": false,
  "approvalStatus": "pending",
  "generation": {
    "provider": "OpenAI GPT Image",
    "model": null,
    "channel": "待填写",
    "generatedAt": null,
    "promptFile": null,
    "referenceFiles": [],
    "postProcessing": []
  },
  "animation": {
    "frameWidth": 64,
    "frameHeight": 64,
    "frameCount": 4,
    "fps": 4,
    "loop": true,
    "anchorX": 32,
    "anchorY": 56,
    "fallbackFrame": 0
  }
}
```

正式构建所使用的素材需有明确来源和可用状态；自制资源也记录作者与制作方式。图片生成使用的参考图同样保留来源说明。

## 7. 可复制的 AI 素材提示词

以下提示词用于 GPT Image 的生成或编辑流程。动作生成时附上已经确认的角色定稿，不仅用文字描述同一角色。

### 7.1 角色静态设计

使用前填写角色形象和配色，不让工具自行决定项目核心形象。

```text
为移动端像素社区“像素小院”设计一个原创 2D 像素角色。
角色形象：[填写，例如戴草帽的小动物]。
主要配色：[填写 3～5 个颜色]。
正面站立，全身完整，轮廓清楚，表情亲切。
以 64×64 像素角色的可读性为目标，色板有限，边缘清晰，避免写实纹理和复杂阴影。
角色居中，四周留出动作空间，脚底位置统一。
仅输出单个角色，不包含文字、水印、场景或 UI。
若工具支持，使用真实透明背景；不要把棋盘格画进图像。
该图用于静态角色定稿，不需要同时生成多种服装或姿势。
```

### 7.2 角色动作参考

```text
使用提供的角色定稿作为唯一角色参考，保持轮廓、服装、配色、比例和面部特征一致。
动作：[待机眨眼 / 点击下蹲后跳起 / 开心举手]。
按以下关键姿势制作：[逐项填写]。
每帧使用相同尺寸、相同视角和共同脚底基线，跳跃位移必须是动作本身的一部分。
无相机移动、无缩放、无新增道具、无文字、无水印。
目标是可修整的连续帧参考；不要用模糊过渡或运动拖影代替姿势变化。
若无法严格生成对齐的精灵图，请分别输出关键姿势，后续用像素编辑器排版。
```

### 7.3 小院背景

```text
设计一个原创、轻松温暖的像素小院背景，服务于移动端 H5 社区。
视角：[填写已确定视角]；配色：[填写统一色板]。
中央为角色留出活动空间，为吃瓜摊、留言牌和信箱预留位置。
地面和装饰简洁，保证上方的独立角色及交互物件容易辨认。
不绘制角色、不绘制按钮、不写任何文字，不将入口标签画进背景。
避免复杂透视、写实材质和密集装饰；布局需便于不同屏幕裁切或扩展。
```

## 8. 给开发 AI 的动画接入提示词

```text
先读取现有角色组件、页面状态和 assets-manifest.json。
本次只实现角色动画资源接入，不修改发帖、评论或权限规则。
使用 PixiJS AnimatedSprite 和现有 React 集成方式，按资源元数据处理静态图和精灵图，支持 idle、pressed、success、error、static 状态。
把自定义清单适配为有序纹理帧，正确转换 fps 与像素锚点，设置最近邻采样，不直接把清单作为 PixiJS 图集 JSON 加载。
使用播放器的播放、停止、循环和完成回调，不自行用定时器逐帧播放；确认首帧、末帧和循环边界不出现空白。
```

## 9. 素材与动画验收

- 图片尺寸、帧数、排列、透明度与元数据完全一致。
- 同一角色不同动作没有服装、颜色、比例或五官的非预期变化。
- 在原始尺寸、2 倍和 3 倍放大下检查边缘，不混入模糊滤镜。
- 精灵图包含全部有效帧，没有空白尾帧；非循环动作能稳定结束。
- 动作由 AnimatedSprite 播放，实际时长与 fps 配置一致，锚点转换正确；切换动作时旧回调不会覆盖新状态。
- 场景挂载、卸载和再次进入不遗留重复画布或更新循环，渲染失败时 HTML 功能入口仍可操作。
- 在浅色和深色底上检查透明边缘，排除残留底色和假棋盘格。
- 场景入口由可访问 HTML 按钮承载，不能只存在于图片中。
- 首屏资源满足预算或提供实际测量与优化说明。
- 来源、许可、所需署名和修改记录完整。
- 保留可编辑角色源文件、动作标签与导出说明；源文件更新后可重新导出有效资源，失败不会覆盖上一份可用产物。
- 导出后的帧顺序和播放时长与源文件一致，资源清单中的来源和生成记录未被覆盖。
- GPT Image 素材的提示词、参考图、生成渠道和后期处理可追溯；不可获取的模型信息如实记录，不猜测版本。
- 浏览页面和触发角色动作不会请求图片生成服务，运行资源均从项目静态资源或其 CDN 加载。
