# AI 开发任务清单

当前全部开发任务均未开始。按依赖顺序执行；每完成一项，核对交付物和验收标准后再勾选。

## 1. 执行规则

1. 阅读项目规则、全部需求文档和即将修改的文件。
2. 发现需求冲突或关键决策缺失时先确认；不得把建议值当成用户已确认的事实。
3. 列出本次方案、涉及文件与验收方式，方案确认后再修改。
4. 每次只完成明确的一组任务，最小化改动，不顺手重构。
5. 所有文本文件使用 UTF-8 无 BOM；每个新方法补充详细中文注释。
6. 完成后只审查修改文件及必要的调用影响；不要求执行 lint。
7. 涉及数据、权限或状态流转时运行有意义的验证，不能把“代码已生成”当成“验收已通过”。

## 3. 任务详情

### [ ] T00 确认产品基线

- 输入：产品需求第 2 节待确认项。
- 工作：确认页面形态、吃瓜来源、匿名方式、审核方式、美术方向；选择其余技术和部署方案。GPT Image 素材来源及 React＋PixiJS AnimatedSprite 动画方案已确定，继续确认角色形象、配色、生成渠道与预算。
- 素材工具准备：按 GPT Image＋Aseprite 的首选流程检查工具可用性、许可和预算；如采用 LibreSprite 或 Piskel，记录对应的可编辑源文件及导出方式。图集打包工具不作为首版必要依赖。
- 交付：在产品需求中逐项记录确认结果，并同步相关文档。
- 完成标准：原型的视觉和功能方向已明确；后端、素材采购、正式部署分别具备所需决策。
- 允许部分推进：后端选型未确认时，可以先做前端模拟原型；不启动依赖未确认选择的工作。

### [ ] T01 初始化工程

- 依赖：T00 中工程选型确认。
- 工作：建立项目、基础路由、样式、共享输入规则位置、环境变量示例和启动说明。
- 交付：可启动的最小工程；说明如何运行及哪些功能尚未实现。
- 验证：启动开发服务器并访问首页；运行适用的类型检查或构建，记录结果。
- 完成标准：无占用真实服务密钥的要求即可启动；没有用空页面伪装已完成功能。

### [ ] T02 实现静态首页与内容骨架

- 依赖：T01。
- 工作：小院、主角占位、三个场景入口、底部文字入口、各页面骨架。
- 交付：手机和桌面可浏览的静态原型。
- 验证：320px、390px 和 1440px 视口检查布局、点击区域、文字和直接路由访问。
- 完成标准：入口含义清晰，素材失败时仍可进入业务页面，无横向滚动。

### [ ] T03 建立 PixiJS 场景与角色原型互动

- 依赖：T02。
- 工作：核对并安装兼容的 PixiJS 依赖，选定直接封装或 @pixi/react 集成；建立客户端场景，用静态 Sprite 和 ticker 做微动，以占位帧验证 AnimatedSprite；建立动画状态、优先级和静态模式。HTML 气泡和按钮使用 CSS。
- 交付：不依赖正式素材的场景与角色组件、可访问操作入口，以及 React 与场景通信约定。
- 验证：连续点击、键盘触发、热点缩放定位、离开及返回页面、异步初始化时卸载、减少动态效果和渲染失败降级。
- 完成标准：同一场景没有重复实例或更新循环，资源与监听清理正确；动作可恢复且不阻塞业务操作，原型使用的动画接入方式可直接替换正式素材。

### [ ] T04 使用 GPT Image 制作并登记素材

- 依赖：T00 中美术方向确认，生成渠道及像素编辑工具可用。
- 工作：先用 GPT Image 制作主角定稿及风格一致的场景、独立道具和动作参考；在 Aseprite 中修整像素、统一色板和尺寸，用同一源文件制作 idle/pressed/success 标签。简单眨眼和呼吸通过修改定稿制作，较复杂姿势可用 AI 参考补帧。按钮、文字和简单气泡由前端实现。
- 执行顺序：静态主角 → 场景与道具 → 静态预览 → 可编辑动作源文件 → 洋葱皮及循环检查 → 自动导出 → 资源登记；不要求一次生成整套可用精灵图。
- 自动化：提供项目导出入口，调用已核对的编辑器导出能力并适配标签、帧顺序和时长，输出第 5 份文档规定的逐动作横排 PNG 及配置。先校验再更新，保留清单中的来源记录；备选编辑器不支持相同自动化时明确记录实际方式和未完成项。
- 交付：可编辑源文件、项目内资源文件、导出入口及说明、assets-manifest.json、生成提示词与参考图记录、来源与适用条款记录、待机/点击/成功预览。
- 验证：透明背景、同帧尺寸、角色比例、脚底锚点、导出边缘与放大效果；修改源文件后重新导出，检查标签、帧顺序、播放时长及生成记录保持正确，失败不覆盖有效产物。
- 完成标准：素材来源可追溯；未获授权素材仅保留为待处理项，不混入正式交付。
- 替代方案：正式素材未完成时，交付自制占位素材并明确标识。
- 运行边界：素材提前生成并作为静态资源交付，不为用户浏览或点击角色增加 GPT Image API 调用。

T04 子步骤：

- [ ] T04.1 确认工具可用，记录生成渠道及编辑器版本。
- [ ] T04.2 完成角色定稿与独立场景素材。
- [ ] T04.3 保存可编辑源文件，制作三个动作标签并完成预览检查。
- [ ] T04.4 建立导出入口和元数据转换，验证失败保护及记录保留。
- [ ] T04.5 完成素材登记、静态与动画预览；集成到应用的验收在 T10 执行。

### [ ] T05 用模拟数据完成内容流程

- 依赖：T03。
- 工作：话题列表/详情/发帖/评论，留言列表/详情/回复，信箱和状态展示。
- 交付：可以完整点击的演示版本，明确显示演示模式。
- 验证：加载、空列表、超长文本、纯空白、失败保留输入、重复点击、离开未提交表单。
- 完成标准：AC01～AC04 的界面流程可演示；不声称已实现真实权限或数据持久化。

### [ ] T06 实现数据库与匿名身份

- 依赖：T01，匿名身份、技术栈、数据保留方向确认。
- 工作：数据迁移、访客和会话、Cookie、统一鉴权、个人接口缓存规则、共享限流基础。
- 交付：数据结构、会话服务、配置样例和身份说明。
- 验证：两套独立浏览器上下文；缺失、过期和伪造凭证；服务端不信任客户端作者 ID。

### [ ] T07 实现吃瓜接口

- 依赖：T06，吃瓜来源及审核规则确认。
- 工作：分页、详情、创建话题、一级评论、作者删除、审核可见性过滤、幂等提交。
- 交付：替换模拟数据的吃瓜服务与页面。
- 验证：输入边界、重复请求、同标识不同正文、跨访客删除、父话题不可见和分页边界。
- 完成标准：AC03、AC05～AC08 中吃瓜部分通过；审核前不对外公开。

### [ ] T08 实现留言与信箱

- 依赖：T07。
- 工作：留言及一级回复；汇总自己的内容；通知列表、已读、来源可见性检查。
- 交付：留言板和信箱接入数据库，具备审核通过时创建通知的服务能力。
- 验证：跨访客访问、自己回复自己、父留言隐藏、通知来源删除、通知唯一性。
- 完成标准：AC04、AC06～AC09 中相关部分通过；通过审核的回复才进入接收者信箱。

### [ ] T09 实现审核与举报

- 依赖：T06～T08，管理员认证方式确认。
- 工作：管理登录、审核队列、通过/拒绝/隐藏、举报提交与处理、事务和操作记录。
- 交付：受服务端授权保护的管理页面与接口。
- 验证：普通访客调用管理接口、重复举报、并发审核、重复通知、父对象不可见时审核回复。
- 完成标准：AC05、AC07、AC09、AC10 通过；管理状态变化与前台展示一致。

### [ ] T10 接入正式动画素材

- 依赖：T03、T04。
- 工作：通过资源配置替换占位角色，适配有序纹理帧并使用 AnimatedSprite 播放；配置速度、循环、完成回调、归一化锚点与最近邻采样，保留静态与素材失败降级。
- 衔接：使用 T04 已导出的文件和配置，不在浏览器中解析编辑器源文件或调用导出工具；如后续改用 TexturePacker 图集，先同步加载格式及元数据适配方案。
- 交付：完整待机、点击、提交反馈及配置文件。
- 验证：帧边界、播放时长、循环复位、动作抢占、缩放、后台暂停、减少动态效果及素材体积预算；检查纹理共享和卸载清理。
- 完成标准：业务逻辑不因美术替换改变，动画不出现空白帧或非预期位置跳动。

### [ ] T11 全流程联调与审查

- 依赖：T05～T09。
- 工作：移除正式路径上的模拟数据；串联发布、审核、公开、回复、通知、举报、隐藏和删除。
- 交付：验收记录，按 AC01～AC12 标注通过/未通过/未验证并说明证据。
- 验证：两个匿名访客与一个管理员分别执行端到端流程；重点复核改动文件的类型、引用和边界。
- 完成标准：无阻断问题；失败项已经修复或明确为未完成，不能用未运行的检查冒充通过。

### [ ] T12 交付与部署准备

- 依赖：T10、T11，部署目标和运行配置确认。
- 工作：完善启动、迁移、配置、部署、数据保留和基础故障处理说明；确认演示数据不进入正式库。
- 交付：可部署项目、素材清单、验收记录和待办清单；有授权和环境时再执行部署。
- 验证：按说明在目标环境执行构建与必要迁移，检查首页和完整发布审核链路。
- 完成标准：交付说明可复现；未部署时写“已准备部署”，不能写“已上线”。
