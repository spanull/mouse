## 1. 已确认范围与方法

用户要求用已验证的 GPT 生图接口替换全部现行运行图片，保持原型图风格；多个素材同时制作，接口失败立即重试并反馈错误原文，质量不通过则修改提示词重新生成，全部检查通过后结束。

采用 AI Coding Gateway 的 `gpt-image-2.5`，`quality=medium`。本轮全部请求实际使用 `/v1/images/generations` 携带 `image` 参考图；`/v1/images/edits` 的调用方式已记录在 08，尚未单独实测。参考原型保存在 `art-source/reference/user-prototype.png`，仅用于风格生成，没有截图裁切作为运行素材。

## 3. 质量检查与修正

1. 原图逐组对照参考原型：苔藓小屋、暖棕描边、木质柜台、柔粉／绿／淡紫、圆润角色和像素纹理；三个场景没有被生成成手机截图或带字 UI。
2. 角色网格切为六种关键姿势，检查完整肢体、同一服装、毛色与轮廓；按同一角色共享缩放和脚底线整理。idle 为站立／轻微上移／站立／闭眼，pressed 为站立／下蹲／跳起／落地，success 使用举手和挥手帧。
3. 首版鼹鼠有明显外耳和细长尾巴，形象像老鼠，**未通过**。保留 `mole-rejected-v1.png/.json`，修改提示词为无外耳、无可见尾巴、尖长鼻和铲形前爪，取消额外老鼠图参考后重新生成。第二版通过角色检查。
4. 生成器部分图片返回真实透明，部分返回品红底。导出阶段保留 Alpha 或去除品红色键；检查没有假棋盘格、色键残留、裁断耳朵／尾巴／杯脚。
5. 34 张透明运行图均有透明与可见像素，尺寸与清单一致，程序扫描未检出品红色键残留；透明图在奶油底预览检查通过。
6. 页面检查发现鼹鼠站在吧台表面、客鼠偏低。用同一场景背景的吧台区域做前景遮挡，调整鼹鼠及访客位置，并补偿手机高画布留白；复查通过。
7. CSS 饮品替换为透明图片，送酒位移动画保留。主场景仍为角色与提示牌；点击、评价、配额、留言和审核规则没有改动。

图片只宣称通过本轮屏幕与运行检查，不宣称存在 Aseprite 源文件、逐像素人工补帧或完整摇酒调酒动作。后者保持后续任务。

## 4. 接口失败原文及处理

首版鼹鼠第一次、睡鼠前两次请求均失败，错误原文为：

```text
curl: (56) schannel: server closed abruptly (missing close_notify)
Expecting value: line 1 column 1 (char 0)
```

第二行是客户端在空响应上解析 JSON 时的错误。没有收到可解析的服务端 JSON 错误，不推测服务端原因。按用户指示无额外等待立即重试：睡鼠第 3 次成功；首版鼹鼠第 2 次成功但视觉检查不通过；修改后的鼹鼠首请求成功。其余 9 组素材均首请求成功。

## 6. 可重复制作与保护

- `scripts/generate-gateway-assets.py`：默认 4 项并发、单项独立立即重试、失败错误反馈、原图与提示词落盘、跳过已有成功产物。需要当前进程 `GATEWAY_API_KEY`。
- `scripts/prepare-gateway-assets.mjs`：去背景、切帧、统一锚点、透明 PNG 输出与清单记录。重新导出后把验收状态置为待复验。
- 原两个占位生成器增加入口保护，检测到 `worldV2.generation` 后报错退出，防止误覆盖 AI 图和来源。
- 保留现有 PixiJS 播放器，读取新帧尺寸与锚点，仍用最近邻采样与既有帧率，减少动态效果和错误降级继续生效。
- 页面不调用网关；不会因访问、点击或留言产生生图费用。

真实后端、AI 内容审核、Aseprite 精修、完整调酒动作、中文像素字体、真机性能和服务商条款复核仍沿用后续任务，不在本轮声称完成。
